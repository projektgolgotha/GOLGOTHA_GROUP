# SydTek Seminary build chunks

This is the execution sequence for the Seminary pathway inside the existing SydTek ecosystem. Delivery status is recorded in `DELIVERY_RECEIPT.json`; an authored document is not evidence that an operational service or academic award exists.

| Chunk | Concrete outcome | Acceptance and dependency |
|---|---|---|
| SEM-001 — Canon and source inventory | Versioned 81-entry registry, 12-part delivery map, verified public media URLs, screenshot observations, and unresolved text identities | Exactly 46 OT + 35 NT registry units; every unit assigned once; grouped components retained; no direct recommendation for unresolved text identities or mixed-topic collections. |
| SEM-002 — First teaching release | A live Skool Seminary course with orientation, original study activities, a formative check, and a portfolio assignment; public ENOCH WORLD study map | Read-back of saved lessons and publication status; exact course link; existing Academy courses retained; source links reach the supplied public material. |
| SEM-003 — Faculty pilot | Adopted SEM-000 and SEM-101 materials, named instructors, accessible submission route, clear feedback and review timing, and a small supervised learner cohort | Faculty approve primary readings and rubrics; a learner can submit work privately, receive feedback, revise, and obtain a documented decision. Actual workload and learning evidence recorded. Requires institutional assignment of staff and cohort terms. |
| SEM-004 — Complete the canon teaching | Detailed syllabi, approved readings, original assessments, and reviewed teaching across SEM-102–110; capstone assessment; distinct Ethiopian church-history requirement | All 81 units and each component have an approved edition, a mapped outcome, a teaching sequence, and a reviewable assessment. Resolve Ezra/Sutuel, Tegsats, Josippon, and Ethiopic church-order identity gaps. Metadata matching alone does not complete this chunk. |
| SEM-005 — Academic records | Learner identity and permissions, enrollments, submissions, rubric scoring, reviewer decisions, revisions, academic appeals, and a reproducible record export | Learners can access only their own private work; reviewers have assigned access; completion can be traced to approved assessment evidence. Group progress checkmarks remain distinct from academic decisions. Requires a supported hosting and identity environment. |
| SEM-006 — Institutional authorization and accreditation development | Correct governing documents, jurisdiction decision, institutional and faculty evidence, required operational history, an appropriate accreditor route, and documented applications when authorized | Follow `ACCREDITATION_PATHWAY.md`. Only the relevant authorities can confer legal or accreditation status. No application is described as accepted until its actual decision is documented. |
| SEM-007 — Reusable SydTek Learn product | Reuse the same curriculum IDs, source manifest, rubric and records model in the custom LMS application, with optional Shopify commerce integration | Pilot the service with SydTek before offering it to unrelated schools. Tenant separation, backups, accessibility, support, and a documented export path must work. Merchant subscriptions or other paid services require a separately approved commercial launch. |

## Immediate next review

Start with SEM-000 and SEM-101. An academic reviewer should select the primary-text editions, adopt or revise the teaching activities, and specify who will receive and evaluate learner work. The certificate decision remains tied to the existing ECS-300 requirements; the 81-book survey does not silently replace its history, comparison, application, and final-project requirements.

## Platform ownership

The curriculum and source records are portable JSON and Markdown in this repository. Skool is the initial classroom surface, ENOCH WORLD is the public discovery surface, and the existing SydTek Learn application is the future software foundation. Moving the content does not require surrendering its original course codes or source provenance.

The current release does not synchronize Skool membership, Shopify customer accounts, grades, or certificates. A later integration must use supported platform interfaces and verified permissions rather than assumed API capabilities.
